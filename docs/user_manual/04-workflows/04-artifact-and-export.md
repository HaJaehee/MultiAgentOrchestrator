# 산출물 생성과 내보내기

> 상위: [워크플로우 개관](README.md) · 이전: [로스터 편집](03-roster-editing.md) · 다음: [폐쇄망 배포](05-airgap-deployment.md)
>
> 파일: `app/orchestration/engine.py` (추출) · `app/ui/components/artifact_viewer.py` (렌더링) · `app/export.py` (내보내기)

토론이 끝나면 두 가지가 남습니다. **산출물**(코드·문서·다이어그램)과
**대화 기록 전체**입니다. 둘은 다른 경로로 나갑니다.

---

## 산출물 파이프라인

```text
오케스트레이터 합성 응답 (마크다운 본문)
   │
   ▼
_extract_artifacts_from_synthesis()
   │  ``` 로 감싼 코드 블록을 순서대로 파싱
   │  블록 앞의 제목 줄을 탭 이름으로
   ▼
ArtifactItem  ─── DB(ArtifactModel) 저장
   │
   ▼
artifacts_synthesized 이벤트 ──▶ 산출물 뷰어 탭
```

### 종류 판정

| 코드 펜스의 language | `artifact_type` | 렌더링 |
| :--- | :--- | :--- |
| `mermaid` | `mermaid` | 다이어그램으로 그림 |
| `python`, `py`, `typescript`, `javascript`, `bash`, `shell`, `json`, `toml`, `sql` | `code` | 하이라이팅된 코드 |
| 그 외 / 없음 | `markdown` | 마크다운 |

합성 자체가 실패하면(오케스트레이터가 엔드포인트에 못 닿음) **아티팩트를 만들지
않습니다.** 실패를 기록으로 남길 뿐, 빈 산출물을 만들어 성공한 것처럼 보이게
하지 않습니다.

---

## 산출물 뷰어

각 산출물이 탭 하나입니다. 탭마다:

| 조작 | 동작 |
| :--- | :--- |
| **복사** | 클립보드로 (`app/ui/clipboard.py`) |
| **다운로드** | 종류에 맞는 확장자로 파일 저장 |

### Mermaid 렌더링

Mermaid 블록은 다이어그램으로 그립니다. 문법 오류가 있으면 **오류를 표시하고
원본 소스를 보여줍니다** — 빈 상자를 남기지 않습니다. LLM 이 만든 Mermaid 는
문법이 어긋나는 일이 흔하므로, `normalize_mermaid()` 가 흔한 문제(따옴표,
줄바꿈, 노드 라벨의 특수문자)를 먼저 정리합니다.

## 대화 기록 내보내기

`app/export.py` 가 대화 하나를 **마크다운 문서 한 장**으로 만듭니다.

```text
# {대화 제목}

| 항목 | 값 |
| --- | --- |
| 생성 | 2026-08-30 14:22 |
| 최종 수정 | 2026-08-30 15:07 |
| 토론 전략 | 순차 토론 (Sequential Debate) |
| 최대 라운드 | 3 |
| 참여 에이전트 | orchestrator, architect, coder, critic |
| 작업 공간 | D:\work\project-a |

## 세션 전용 지침
...

## 발언 기록
### 🙋 사용자
### 🧭 오케스트레이터  (Round 0)
### 🤖 System Architect  (Round 1)
   └ 🔧 filesystem__read_text_file  ▸ 인자 / 결과
### ⚠️ 실패 — Security & Quality Critic

## 최종 산출물
...
```

| 표지 | 발언 종류 |
| :--- | :--- |
| 🙋 사용자 | `user` |
| 🧭 오케스트레이터 | `orchestrator` |
| 🤖 에이전트 | `agent` |
| ⚠️ 실패 | `error` |
| ⚙️ 시스템 | `system` |

**누가 무슨 자격으로 말했는지가 한눈에 보여야** 합니다. 실패도 기록에 남으므로,
문서를 읽는 사람이 "네 명이 합의했다" 와 "두 명이 침묵했다" 를 구분할 수 있습니다.

### 설계 두 가지

**순수 함수입니다.** DB 를 모릅니다. 화면이 읽어 온 값을 넘기기만 하고, 이
파일은 그것을 문서로만 바꿉니다. 그래서 테스트가 DB 없이 돕니다.

**전략 이름은 지금 값을 씁니다.**

```python
("토론 전략", get_strategy(session.get("strategy")).display_name)
```

저장된 키가 아니라 **이 대화가 실제로 도는 전략**의 이름을 적습니다. 예전
이름(`free_debate`)으로 저장된 대화는 이어서 진행하면 지금 전략으로 돌아가므로,
문서에 없어진 키를 남겨 두면 **그 문서가 거짓말을 하게 됩니다.**

### 도구 기록의 중복 방지

도구 실행 기록은 보통 발언에 붙어 나옵니다. 어느 발언에서 나왔는지 기록이 남지
않은 항목만 문서 끝에 따로 모읍니다 — 발언에 붙은 것을 여기서 또 보여주면 같은
내용이 두 번 나옵니다.

### 파일 이름

```python
safe_filename("JWT 인증 설계", when=created_at)
# → "JWT_인증_설계_20260830-1422.md"
```

Windows 에서 쓸 수 없는 문자를 걸러내고, 제목이 비어도 날짜로 이름이 남습니다.

## 시각 처리

DB 에는 **UTC 로 저장**하고(`utc_now()`), 문서에 쓸 때 로컬로 옮깁니다
(`to_local()`). 파일 이름의 타임스탬프도 같은 값을 씁니다 — 문서 안의 시각과
파일 이름이 어긋나면 안 됩니다.

---

## 산출물은 어디에 남는가

| 위치 | 무엇 | 세션 삭제 시 |
| :--- | :--- | :--- |
| DB `artifacts` | 합성된 코드·문서·다이어그램 | 함께 삭제 |
| 작업 공간 폴더 | 에이전트가 MCP 로 **실제로 만든 파일** | **남음** |
| 내보낸 마크다운 | 사용자가 저장한 위치 | 무관 |

작업 공간 파일이 남는 이유: 에이전트가 만든 파일은 대화 기록과 별개의
산출물이고, 여러 대화가 같은 폴더를 공유할 수도 있습니다. git MCP 서버를 켜
두었다면 라운드별 변화가 커밋으로도 남습니다.
