## 관통하는 세 가지 원칙

### 1. 실패를 숨기지 않는다

시스템 어디에서도 "그럴듯한 대체물" 을 만들지 않습니다.

| 상황 | 하는 일 | 하지 않는 일 |
| :--- | :--- | :--- |
| LLM 엔드포인트 불통 | 그 발언을 실패로 기록하고 합성 프롬프트에 알림 | 대신 문장을 생성 |
| MCP 서버 연결 실패 | 상태 칩에 표시, 그 도구 없이 진행 | 도구 실행을 흉내 |
| 도구 루프 한도 소진 | `LLMUnavailableError` 발생 | 자리표시자 답변 반환 |
| 설정 문법 오류 | 줄 번호와 함께 거부, 실행 중 설정은 그대로 | 부분 적용 |

이것이 없으면 **토론 기록을 신뢰할 수 없습니다.** 네 에이전트가 합의한 것처럼
보이는 문서가 사실은 세 명이 침묵한 결과일 수 있기 때문입니다.

### 2. 배포 설정과 대화 상태를 섞지 않는다

```text
conf.json (배포 설정)              SQLite (대화 상태)
├── 에이전트 목록                  ├── 발언 기록
├── 모델 · 엔드포인트 · 키          ├── 도구 실행 기록
├── 도구 권한                      ├── 산출물
├── 발언 순서 · 진영                ├── 페르소나 초안
└── MCP 서버                       └── config_snapshot ← 잠긴 시점의 배포 설정 사본
     │                                    ▲
     └──── 첫 메시지에 여기로 굳음 ─────────┘
```

시작한 대화는 `conf.json` 을 더 이상 읽지 않습니다.
→ [데이터베이스와 세션 스냅샷](07-persistence.md)

### 3. 하드코딩된 에이전트 키가 없다

예전에는 전략 코드에 `{"architect": 0, "coder": 1, "critic": 2}` 같은 표가
있었습니다. 화면에서 에이전트를 만들 수 있게 되면서 그 방식은 무너졌습니다 —
표에 없는 키는 전부 맨 뒤로 밀렸고, 디베이트에서는 어느 진영에도 못 들어갔습니다.

이제 **순서와 진영은 에이전트 자신이 들고 다닙니다** (`debate_priority`,
`debate_stance`). 코드에 에이전트 키가 나타나는 곳은 오케스트레이터를 라운드에서
빼는 한 줄뿐이고, 그것은 역할이 아니라 구조입니다.
→ [토론 전략](06-debate-strategies.md)
